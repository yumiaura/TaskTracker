Claude Code и так ведёт список задач, пока работает, — и этот список умирает вместе с сессией.<br>
TaskTracker его сохраняет: каждая задача, которую Claude пишет, зеркалится на доску проекта.<br>
В следующей сессии он читает очередь обратно и может сам класть на доску новые задачи через MCP-инструменты.<br>
А ты смотришь на это в локальной веб-панели: список проектов, а внутри три колонки — **в очереди**, **в работе**, **выполнено**.

## 🚀 Быстрый старт

```bash
pip install -e .
```

Дальше в Claude Code:

```
/plugin marketplace add /путь/к/TaskTracker
/plugin install tasktracker@tasktracker
```

Перезапусти — и с этого момента каждый `TodoWrite` попадает на доску, MCP-сервер
`tasktracker` подключён, `/tasktracker:tasks` показывает очередь текущего проекта,
а `/tasktracker:tasks-panel` открывает панель.

Вручную:

```bash
tasktracker serve --open      # http://127.0.0.1:8787/
tasktracker where             # где лежит база
```

Панель слушает только `127.0.0.1` и не имеет авторизации — именно поэтому она слушает
только там. `TASKTRACKER_HOST` и `TASKTRACKER_PORT` переопределяют значения по умолчанию.

## 🧩 Как доска заполняется сама

1. **Хук.** Хук `PostToolUse` на `TodoWrite` зеркалит собственный todo-список Claude на
   доску того проекта, в котором он работает. Ничего вызывать и ничего помнить не нужно.
   Только стандартная библиотека — работает ещё до того, как что-либо установлено.
2. **MCP-инструменты.** Для работы, которая **не** входит в текущий план: следующий шаг,
   что-то замеченное по пути, что-то на потом, — и чтобы прочитать очередь в начале сессии.
3. **Панель.** Набрать карточку, перетащить между колонками, отредактировать или удалить.

## 🛠 MCP-инструменты

| Инструмент | Что делает |
| --- | --- |
| `tasks_queued` | Что ждёт и что в работе. Вызывать в начале работы над проектом. |
| `tasks_all` | Все карточки, включая выполненные. |
| `task_add` | Положить задачу на доску. |
| `task_start` / `task_done` | Перевести в «в работе» / отметить выполненной. |
| `task_update` / `task_delete` | Изменить название, описание или колонку / удалить карточку. |
| `projects_list` | Все проекты доски со счётчиками. |

Каждый определяет проект по директории, в которой запущена сессия, поднимаясь до корня
репозитория, — так что сессия в `~/src/app/web` пишет в проект `app`. У каждого
инструмента есть и явный `project`: имя, путь или id.

## ⚙️ Настройки

Одна настройка на экране настроек: **через сколько дней выполненная задача пропадает с
доски**. Это фильтр на выдачу API, а не удаление — подними число, и карточки вернутся.
`0` оставляет выполненные задачи на доске навсегда.

Тема и выбор «доска / таблица» живут в браузере — они про экран, за которым ты сидишь.

## 💾 Где лежат данные

Один файл SQLite, `~/.claude/tasktracker/tasks.db`, общий для всех проектов;
`TASKTRACKER_HOME` его переносит. Пишут в него три процесса — панель, MCP-сервер и хук, —
поэтому он работает в режиме WAL с busy timeout и берёт блокировку на запись сразу.

<details>
<summary><b>HTTP API</b> — всё, что делает панель, она делает через него</summary>

Любая ошибка возвращается как `{"error": {"message": "…"}}`.

| Метод | Путь | |
| --- | --- | --- |
| `GET` | `/api/health` | жив ли сервер и какой файл открыт |
| `GET` | `/api/projects` | все проекты со счётчиками |
| `GET` | `/api/projects/{id}` | проект, его карточки и настройки |
| `DELETE` | `/api/projects/{id}` | убрать проект вместе с карточками |
| `POST` | `/api/projects/{id}/tasks` | добавить карточку |
| `PATCH` | `/api/tasks/{id}` | изменить; не переданное поле не трогается |
| `POST` | `/api/tasks/{id}/move` | `{status, index}` — положить в колонку |
| `DELETE` | `/api/tasks/{id}` | удалить карточку |
| `GET` `PUT` | `/api/settings` | настройка «прятать через N дней» |

</details>

## 🧪 Разработка

```bash
pip install -e '.[dev]'
python3 -m pytest tests -q
python3 -m ruff check src tests
```

У панели нет шага сборки: `www/` отдаётся как есть, `.vue` грузятся в браузере через
`httpVueLoader`, все библиотеки лежат в `www/vendor`. Четыре теста обходят каждый путь,
который называют `index.html`, `main.css` и `app.js`, и проверяют, что файл действительно
поставляется, — иначе пропавшую вендорную библиотеку никто не заметит, пока её не запросит
браузер.

Палитра, размеры контролов и верхняя панель взяты из
[`wachawo/lmgateway`](https://github.com/wachawo/lmgateway), чтобы два инструмента читались
как одна семья.
